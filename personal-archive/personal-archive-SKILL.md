# 个人档案 · 读写与管理协议（通用版 v1.2）

用户的"个人档案"是**给人看的那一层**：身份、工作方式、固定规范、关键决策。它按板块组织、
用散文体写、由用户自己翻阅。本协议让任意 agent 都能**按同一套规矩**读它、写它、维护它。

> **与记忆库的分工**：档案是「人读层」，`shared-agent-memory` 是「机读层」。两者
> **分开存储、分开管理、互不镜像**，只有「对 agent 有用」的档案信息才允许**单向、逐条**
> 放行到记忆库。详见下文「四、与记忆库的边界」。

## 一、档案根目录（唯一权威解析规则，必须严格按序）

```
ArchiveRoot 解析顺序：
1. 环境变量 PERSONAL_ARCHIVE_ROOT 已设置 → 用它（绝对路径）
2. 否则 → 本 SKILL.md 文件所在目录下的 ./archive
```

⚠️ **不是当前工作目录（CWD）**。agent 通常在用户的项目目录里执行任务，按 CWD 解析会读到
无关目录，或凭空造出一套影子档案。

**禁止**把 ArchiveRoot 硬编码成机器绝对路径（`/Users/...`、`C:\Users\...`）：
既不可移植，也会被 `scripts/pre-push-check.sh` 判为隐私泄漏。

多设备 / 多 agent 指向同一份档案，两种做法：

1. **软链（本机多 agent 首选，最稳）**：把各 agent 技能目录下的 `archive/` 做成软链，统一指向
   同一份真档案（安装器一条命令：`bash install.sh --update --link-archive "<真档案路径>"`）。
   此时"本 SKILL.md 同目录下的 `./archive`"恰好落到同一处——**不依赖环境变量，也不依赖 agent
   的启动方式**（GUI 启动的 app 常常读不到 shell 环境变量，只靠方式 2 会静默失效）。
2. **环境变量**：导出 `PERSONAL_ARCHIVE_ROOT=<真档案路径>` 后再启动 agent。

## 二、适用范围

**管什么**

1. 档案内的**任何书写动作**：新增一篇、改写一篇、归档、刷新索引。
2. 档案的**体例合规**：目录结构、frontmatter、正文禁令（见「三、硬性规范」）。
3. 档案与记忆库之间的**边界判定**（什么内容允许从档案放行到记忆库）。
4. 所有读取本协议的 agent（本机每个技能目录各一份副本，含以后新增的）。

**不管什么**（走别的协议或不走协议）

- 机读记忆的读写 → 走 `shared-agent-memory`。
- 原始记录（第 0 层：各 agent 的会话存档）→ **留在原地，不搬动、不比对**。
- 项目 / 技术类事实（端口、路径、构建配置、工具链）→ 不属档案，直接进记忆库。
- 公开知识（配方、术语、公开资料、方法论本身）→ 两处都不进。

## 三、硬性规范

### 目录体例（板块目录名即主题，篇目文件名即主题）

| 位置 | 放什么 |
|---|---|
| `总索引.md` | 全档索引：板块说明、篇目清单、维护约定 |
| `画像/` | 我是谁：身份、背景、资源条件、目标 |
| `周志/` | **每周一篇**的周记：本周关键事件、决策与取舍、录音与对话要点、下周待办（文件名用 ISO 周键） |
| `规范/` | 固定规则：什么该留、界面与交付、隔离与放行 |
| `决策/` | 拍过板的决定：为什么这么定、备选与取舍（文件名带日期前缀） |
| `财务/` | 收支概览与索引（原始账单归档在档案之外，档内只留概览与索引） |

**板块是可扩展的：上表是"当前板块"，不是封闭集合。** 新增板块直接建同名目录，并同步做两件事：

1. 在 `总索引.md` 里补上该板块的说明与篇目登记；
2. 新板块的命名与既有板块保持同一风格（两到四字的名词，如 `健康/`、`学习/`）。

`doctor.sh` **动态识别**顶层目录、不限定板块名称，因此**新增板块不需要改脚本**。

- **一模块一篇**：多主题拆成多篇，不写超长合订本。
- **文件名即主题**，不写数字编号前缀；需要时间维度的板块用固定前缀：
  **周志 = `YYYY-Wxx 周志`**（ISO 周键承担排序）、决策 = 「日期 + 主题」、财务 = 「年度 + 主题」，
  其余板块直接写主题。

### 周志规范（周粒度，唯一时间序列载体——不设日志板块）

周志是档案里**唯一按时间连续记录**的载体；档案**不设、不保留「日志」板块**。写它时守以下几条：

0. **不设日志板块**：逐日记录、录音转写整理稿一律并入当周周志，不再单独成篇、
   不在档案里保留 `日志/` 类逐日目录；录音转写**原文不入档案**，如需整篇留档，
   只进档案外的备份容器（桌面备份 / git 历史）。

1. **每周一篇**：同一 ISO 周只允许一个 `YYYY-Wxx 周志` 文件，不逐日成篇、不为同一天再开新篇。
2. **素材优先级**：用户的「本周自总结」是主素材；IMA 随思（每周写的随笔原文）与录音转写为辅。
   三者冲突时以自总结为准，辅素材只用来补细节、找遗漏。
3. **结构**：`本周记录`（按日或按主题分条）→ `本周关键词` → `下周`。
   可加 `决策与取舍`、`录音与对话要点` 两节，但不再复述完整转写。
4. **体积纪律**：单篇正文目标 ≤ 6KB；宁可写要点 + 小节索引，不搬运整段转写。
   压缩前的逐日原文必须先在档案外留档（备份容器 / git 历史）再合并。
5. **AI 参与**：AI 生成的周报段必须标注「⚠️ 由 AI 生成，请按需取舍后再归档」，
   与用户原话、随思原文分区呈现，不混写。
6. **录音**：音频本体**不入档**，只留标题、日期、体积与（临时）链接；
   转写要点进周志正文。标题带 `YYYY-MM-DD` 才按标题日期归周，
   无日期录音按「同步所在周」归入并在文中标 `confidence: low`，不臆造日期。

### frontmatter（必填 4 项；`tags`/`status` 推荐补）

```yaml
---
title: 双仓隔离与放行规则
type: rule            # rule | index | profile | log | weekly | decision | economics | finance（可扩展）
created: 2026-10-15
updated: 2026-10-15
tags: [个人档案, 规范]   # 推荐：便于检索
status: 生效中          # 推荐：生效中 | 已作废 | 草稿
---
```

- **必填**：`title`、`type`、`created`、`updated`（缺失即不合规）。
- **推荐**：`tags`、`status`——不是硬门槛，但便于检索与判定时效；缺失只提示不报错。
- `type` 是开放枚举：上表为常用值，出现新类型时**沿用同一命名风格**即可，不必改脚本。

### 正文禁令（这几条最常被违反）

1. **不写机器绝对路径**：用相对路径或「日期 + 主题」。绝对路径既不可移植也是隐私泄漏。
2. **最小必要脱敏**：证件号、银行卡号、完整手机号、详细住址、账号凭据**不落正文**；
   确需记录时只留尾号、标签或「已另存」的说明。
3. **只增不删**：过时内容标 `status: 已作废` 并注明替代项，不直接抹掉。
4. **跨篇引用**用 `[[个人档案/…]]` 形式，便于在笔记工具里跳转。

> 工具与品牌名（模型、厂商、软件名）**可以正常出现**：档案是人的笔记，提到
> 「用某工具做了某事」是事实陈述，不构成违规。

## 四、与记忆库的边界（双仓隔离）

档案与记忆库是**两个独立仓库**，都派生自原始记录，是**兄弟关系**：

1. **互不镜像**：禁止把档案整篇/整块搬进记忆库，禁止把记忆库当档案副本，
   禁止用记忆库内容回写、覆盖档案。
2. **只放行「对 agent 有用」的内容**（单向、逐条），需三问全过：
   ① **行为改变**——知道它会不会改变 agent 的输出/做法/检索路径？
   ② **自足可读**——不看档案、只读这一条，agent 能否正确行动？
   ③ **最小披露**——能否用更抽象的说法达到同样效果？
   并叠加评分卡硬门槛：**可行动性必须 ≥ 2 分**，否则总分再高也不放行。
3. **红线一票否决**（无论用户是否要求）：证件号、银行卡号、完整手机号、详细住址、账号凭据；
   与 agent 行为无关的私密心事、情感叙述、长篇经历；**档案的目录体例与排版**。
   确需提及这类话题时只写**抽象结论**（如「存在一份花名册，位置 X，迭代规则 Y」），不写个体明细。
4. **两仓冲突时以档案为事实来源**，记忆库修正为「行为结论」；不得反向覆盖。
5. **淘汰互相独立**：档案按自己的保留策略走，记忆库按自身的优先级与复核时限淘汰。

## 五、触发条件（什么时候才动手）

| 触发 | agent 应做什么 |
|---|---|
| 用户说「记到个人档案 / 写进档案 / 更新档案」 | 进入**写入流程** |
| 用户说「档案里是怎么写的 / 我的档案里有没有 X」 | 进入**读取流程**（这是被允许的读取） |
| 用户说「整理 / 复盘 / 归档一下档案」 | 进入**维护流程**（索引刷新、体检） |
| 用户问「这条要不要进记忆库」 | 走 `shared-agent-memory` + 上文三问门控 |
| 只是一次普通任务、没人提档案 | **不动档案**：不主动读、不主动写 |

> **默认静默原则**：档案是用户的私人笔记本，agent 不以"可能有帮助"为由私自翻阅或追加。
> 拿不准时问一句，而不是先写了再说。

## 六、调用方式（流程）

### 读取（仅在触发时）

1. 按「一」解析 ArchiveRoot。**不可读就停下告知用户**，不要凭空新建档案。
2. 先读 `总索引.md` 定位板块，再读目标篇。
3. **只读需要的那几篇**，不要通读全档。

### 写入（仅在触发时）

1. **判板块**：画像 / 周志 / 规范 / 决策 / 财务。判不准先问用户。
   周内发生的事一律并入当周周志，不再新建逐日篇目。
2. **判粒度**：一模块一篇；新主题是否该独立成篇，还是并入既有篇。
3. **写 frontmatter**（按「三」的模板，`created` 与 `updated` 都填当天）。
4. **写正文**：散文体、按主题分节；遵守正文禁令。
5. **挂索引**：在 `总索引.md` 对应板块下补一行链接与一句话说明。
6. **回报**：明确说清改了哪几篇。

### 维护

1. 跑 `bash scripts/doctor.sh <档案目录>` 看结构 / frontmatter / 禁令 / 索引一致性报告。
2. 按报告修：漏挂索引、缺 frontmatter、正文出现机器绝对路径。
3. 归档而非删除：过时篇目标「已作废」+ 替代项。
4. **周志合并**：同一周出现多篇逐日记录时，合并进当周 `YYYY-Wxx 周志`，
   原文先在档案外留档（备份容器 / git 历史），再移除逐日篇与逐日目录；
   合并后重跑体检。**不再回建「日志」类逐日板块**。

## 七、体检

体检脚本在公开仓库的 `scripts/doctor.sh`，可对任意档案路径运行：

```bash
bash scripts/doctor.sh "<档案目录>"          # 体检指定档案
bash scripts/doctor.sh "<档案目录>" --strict  # 有警告也算失败（适合 CI）
```

检查项：总索引与板块目录是否就位（板块动态识别）、frontmatter 是否闭合与必填、
各板块编号风格是否混用、正文是否出现机器绝对路径、是否残留可识别身份字段、
**索引是否漏挂**、SKILL.md 版本。

## 八、入口分拣与提炼（从对话到周志）

用户与 agent 的日常对话是档案的**上游入口**。对话内容先经分拣与提炼，
只有提炼产物才进入周志写作流程，原始对话本身不入档。

### 分拣（看两个信号：有无动作、有无时间）

| 输入特征 | 归类 | 去处 |
|---|---|---|
| 只有想法、点子、感慨，无动作、无截止 | **随思随想** | 收集箱：原话 + 时间戳暂存，不加工 |
| 带明确动作与时间要求（帮我做、去查、提醒我、给出截止） | **工作任务** | agent 的任务追踪，按期交付，其结果回流为周志素材 |
| 对已发生事情的回顾、陈述 | **周志素材** | 当周周桶，等待周日蒸馏 |

- 拿不准时**默认按随思随想暂存**，先保证不丢失；只有疑似带截止时间的任务才当场问一句确认。
- 分类被用户纠正时，把纠正记成规则，同类输入下次直接按新规则分拣。

### 提炼（三层漏斗）

1. **原样层**：收集箱只存原话与时间戳，对应「逐日原文不入档」，
   留存位置是档案外的备份容器或 agent 自己的工作区。
2. **当日提炼**：从当天输入抽出**事实、决定、待办**三类，合并重复，
   一次性闲聊与过期信息沉底。过滤两道：三个月内是否还用得上；
   是可核实的事实还是当时情绪，后者不进提炼稿。
3. **每周蒸馏**：按「三、周志规范」的结构组装草稿（本周记录 → 本周关键词 → 下周，
   可加决策与取舍），**每条标注出处日期**，可逐条溯源，不写无出处的总结。

### 与既有规则的衔接

- 本节产出的蒸馏稿即周志规范所称的**辅素材**；用户的本周自总结仍是主素材，
  冲突时以自总结为准。
- AI 参与生成的段落按周志规范第 5 条标注，与用户原话分区呈现。
- 蒸馏稿写入档案前先列改动点经用户确认，确认制优先于自动入档。
- 提炼中浮现的稳定偏好与决定，按「四、与记忆库的边界」过三问门控后，
  才单向放行到记忆库；本节不改变双仓纪律。

## 九、何时不需要用本协议

- 用户只是在聊天里陈述事实 → 走记忆库协议，**不要**顺手写进档案。
- 一次性任务 → 两处都不写。
- 内容属于原始记录（会话存档）→ 留在原地。
